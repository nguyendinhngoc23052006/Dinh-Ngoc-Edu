# supabase/ — local wiring

- `config.toml` is generated by `npx supabase init` — never hand-write it. Edit only known keys (`[db.seed]`, declared functions/buckets). Leave top-level `project_id` as the folder name: it's a local label, not the remote Project ID.
- `migrations/`: one `YYYYMMDDHHMMSS_description.sql` (UTC) per change, timestamped later than the newest. Never edit a merged migration — add a new one (fix-forward). Every new table ships with its RLS in the same file.
- `seed.sql` must stay idempotent. The baseline migration enables pgcrypto so `crypt()` is available when seeding auth users later.
- `functions/extract-material` runs at upload time (caller's JWT, synchronous): extracts a material's text to `<storage_path>.md` and records the outcome on `course_materials.extract_status`. Shared parsing lives in `functions/_shared/extract.ts`.
- `functions/generate-course` runs with the **caller's JWT** (no service-role key): the owner RLS policies authorize all pipeline writes, so it can only fill courses the caller owns. Heavy work goes through `EdgeRuntime.waitUntil` (202 first, client polls `courses.status`); pure logic stays in `pipeline.ts` so vitest can test it without Deno.
- `clone_course()` copies questions with an EXPLICIT column list — adding a column to `questions` (or chapters/nodes) silently drops to the default on clones unless you also `create or replace` the function (fix-forward) to add the column to both its insert list and select. (Phase 2 added `questions.difficulty` this way.)
