# Repo memory

- `CosmeticsLayer` (the theme applier + roaming pet) is mounted in `AppLayout`, a React-Router layout route with `<Outlet/>`, so it stays mounted across page navigations. Its `useAsync(listCosmetics, [])` and `useAsync(listSpecies, [])` therefore run ONCE per app session, not per navigation (only `getActivePet` refetches, keyed on user/pets_hatched). So there is NO per-navigation refetch cost to "fix" — don't add a cosmetics context provider for that reason.

- Explore's public-catalogue title search (`listPublicCourses`) uses `ILIKE '%term%'` with the LIKE metacharacters escaped — no trigram index, so it's a sequential scan over public courses. Fine while the catalogue is small and always paginated; if it grows large, add a `pg_trgm` GIN index on `courses.title` (and a btree if the title sort gets heavy). Deliberately deferred in Phase 2.

- The on-screen pet companion (`CosmeticsLayer`) renders animated CC0 spritesheets from `public/pets/<species_id>.png` (Ninja Adventure pack, CC0; 64×64 = 4 walk frames × 4 direction rows of 16×16) — keyed by `species.id` by CONVENTION (no DB column; resolver in `lib/petSprite.ts`), with the species emoji as `<Image>`-onerror fallback. It roams the viewport via `usePetWander` (rAF) over pure math in `lib/petWander.ts`. Two gotchas: (1) the facing flip (`scaleX(-1)`) MUST sit on a wrapper, never on the animated frame — a live CSS keyframe that animates `transform` overrides an inline `transform`; (2) the 9 species were renamed to monster names (migration 20260614050000) to match the art, keeping their `spc-*` ids so `pets.species_id` FKs + sprite filenames stay valid. The image-gen MCP (Higgsfield) was the first art choice but the account had 0 credits, so CC0 was used instead.
- Toolchain (scaffolded 2026-06): Node 22 LTS, Vite 8, React 19, TypeScript 6, ESLint 10 (flat config), Vitest 4, Supabase CLI 2.105.
- `npx supabase init` (CLI 2.105) already generates `[db.seed]` with `enabled = true` and `sql_paths = ["./seed.sql"]` — no config.toml edit needed.
- eslint-plugin-react-hooks v7: the flat config lives at `configs.flat.recommended`; `configs['recommended-latest']` is the legacy (eslintrc) shape and breaks ESLint 10.
- Prettier skips all `*.md` (see .prettierignore) so it never reformats the read-only CLAUDE.md constitution files.
- Agents are read-only (Read/Grep/Glob), carry NO model name, and each has a `<name>.memory.md` sidecar the orchestrator updates from the agent's "Memory candidates" report section. Tier is a HIERARCHY resolved at dispatch, never a stored name: the orchestrator's tier is the model the human picked for the session, reviewers (`security/code/scale-reviewer`) run one tier BELOW the orchestrator, and the `researcher` worker (fan-out reading + drafting, returns text, never commits) runs one tier below the reviewers. The orchestrator MUST pass `model` explicitly on every dispatch — omitting it inherits the orchestrator's tier (PR #33 silently ran the reviewers on the top model that way). Before each PR the orchestrator dispatches the three reviewers and records each verdict to `.claude/review/<agent>.md`.
- Stop/SubagentStop hook (`.claude/hooks/stop-check.sh`) verifies, using git + filesystem only: the committed `.claude/pr-body.md` (Self-check heading, all boxes ticked); that the three reviewer verdicts `.claude/review/{security,code,scale}-reviewer.md` each exist AND were refreshed this task (a stale verdict can't pass for a new PR); that none of the three reviewer agent files is missing (the floor guard); and that a memory file changed (or pr-body says "no new lesson"). Write pr-body.md FIRST, then open the PR from its contents. Q&A sessions pass automatically (no commits ahead of main + clean tree). Redesigned 2026-06 because the old gh-based check false-blocked every cloud session (`gh` may be absent there; check `which gh`, never assume).
- eslint-plugin-react-hooks v7 also ships strict `set-state-in-effect` and `use-memo` rules: a generic fetch hook (src/hooks/useAsync.ts) needs targeted disables — moving the setState into a dynamically-depped useCallback just trips the next rule.
- AI calls go through an OpenAI-compatible chat-completions endpoint chosen by Edge Function secrets (`AI_API_KEY`/`AI_BASE_URL`/`AI_MODEL`, default Gemini free tier) — swapping provider (incl. Anthropic's OpenAI-compat layer) is a secrets change, not a code change.
- Supabase Storage object keys reject most non-ASCII characters ("Invalid key") — sanitize user-supplied file names into the key (`materialService.toStorageName`) and keep the original in the metadata row.
- Supabase's built-in mailer allows only a few emails per hour for the WHOLE project (error code `over_email_send_rate_limit`), and the dashboard Site URL defaults to localhost:3000 — for email-only auth the workaround is disabling "Confirm email" (or custom SMTP), plus a correct Site URL/Redirect URLs and `emailRedirectTo`. The auth flows set redirect paths the Supabase Redirect URLs allow-list must include (plus a `https://*.vercel.app/...` wildcard for previews): `/dashboard` (signup confirm via `emailRedirectTo`) and `/reset` (password reset via `resetPasswordForEmail`'s `redirectTo`); a missing entry silently falls back to the Site URL. (Google OAuth was built then backed out by request — 2026-06.)
- Seeding a loginable `auth.users` row by hand: the text token columns (`confirmation_token`, `recovery_token`, `email_change`, `email_change_token_new`) MUST be `''`, never NULL — GoTrue scans them into non-null strings, so a NULL logs in as "Database error querying schema" (the row looks fine until someone tries it; a `signUp()` user works because it sets them). `seed.sql` sets them on insert AND self-heals an older NULL row via an idempotent UPDATE. The `on_auth_user_created`→`handle_new_user` trigger is NOT the cause (it fires on insert only; real signups work).
- Free-tier AI keys are requests-per-minute bound: the question step batches one call per CHAPTER (`node_index` routing), ≤9 calls per course instead of ≤41.
- A Vite SPA on Vercel 404s on hard reloads of deep links unless `vercel.json` rewrites all routes to `/index.html`.
- The uptime monitor's `/health` is a **Vercel Edge Function** at `api/health.ts` (a Vite SPA has no server route, so a client route would return HTML the GitHub Action can't grep). `vercel.json` rewrites `/health → /api/health` BEFORE the catch-all; `tsconfig` includes `api` so the function is typechecked. It round-trips Supabase `/auth/v1/health` (no app tables) and returns plain text `ok` that `.github/workflows/uptime.yml` checks; it reads the public Production env via the two-prefix fallback (no secret). The workflow no-ops when the `PRODUCTION_URL` Actions variable is unset.
- White-screen previews root cause (2026-06): the Supabase→Vercel integration injects preview vars under fixed `NEXT_PUBLIC_` names (not `VITE_…ANON_KEY` as first assumed), Vite only exposed `VITE_`, and supabaseClient throws at import — so React never mounted. Fix: `envPrefix: ['VITE_', 'NEXT_PUBLIC_']` + the two-prefix fallback chain in supabaseClient; production keeps the hand-set `VITE_` names.
- Second white-screen cause: the Supabase GitHub connection's "Supabase changes only" option skips branch creation for PRs that don't touch `supabase/` ("Supabase Preview" check = skipped) — then the Vercel integration injects nothing and the preview has NO Supabase vars under any name. Fix is a dashboard toggle (disable "Supabase changes only"); code-side, main.tsx dynamically imports App so a missing-config throw renders a readable error instead of a white page.
- Third white-screen cause (the decisive one): the Supabase↔Vercel marketplace connection wasn't linked to the CURRENT Supabase project (recreating the Supabase project / renaming the repo orphans it) — looks installed but syncs nothing: no preview-scoped vars, no auto-redeploy. Env sync fires at PR-OPEN (not branch creation or push), so after relinking, close/reopen the PR to trigger it; proof of success is the integration's auto-redeploy (`originalDeploymentId` set on the new deployment) plus a changed bundle hash on identical code.
- Edge Function code with Deno `npm:` specifiers is Vitest-testable by aliasing each specifier to the same pinned package in vite.config `test.alias` (dev-only mirror deps, kept in lockstep with the npm: strings) — no Deno toolchain or separate CI job needed; pure logic stays in helpers per the pipeline.ts pattern.
- Server-side upload gate lives on storage.buckets (`file_size_limit`, `allowed_mime_types`) — set via migration. supabase-js uploads must pass an explicit `contentType` (browsers leave `file.type` empty for `.md`, and the bucket rejects unknown MIME types).
- Text extraction runs at upload time (`extract-material` Edge Function writes `<storage_path>.md` + `extract_status` on course_materials); generate-course reads the .md and only falls back to inline parsing for pre-feature rows.
- Language drift is tamed by: a system message pinning the language, per-field language rules in the prompts, `response_format: json_object` + temperature 0.2, and a Vietnamese-diacritics post-check with exactly one re-ask. The post-check (`matchesOutputLanguage`) is BIDIRECTIONAL: a Vietnamese course must contain Vietnamese AND a non-Vietnamese course must NOT (catches Vietnamese leaking into an English course — the reported bug). Detection uses Vietnamese-UNIQUE chars only (`đ ơ ư` + tonal block U+1EA0–U+1EF9); `ă â ê ô` are excluded because Romanian/French/Portuguese share them. Pairs without Vietnamese (English↔French) stay undetectable and pass.
- Pure logic shared by the browser AND the Deno Edge Functions lives in `supabase/functions/_shared/` (calc.ts = no-eval formula evaluator for calc questions; grade.ts = exact server re-grade). The client imports it by RELATIVE path (`../../supabase/functions/_shared/...`) — tsconfig has `allowImportingTsExtensions` so grade.ts's `./calc.ts` import resolves; no path alias / @types/node needed. Edge functions import the same files with `../_shared/...`.
- Credits are spendable currency, so the balance is NEVER client-writable: `profiles` revokes blanket UPDATE and grants only `update (pet_enabled)`; credits move only via `award_lesson_credit` (service_role-only RPC) and `purchase_cosmetic`/`equip_cosmetic` (SECURITY DEFINER). A flawless lesson is verified by the `complete-lesson` Edge Function (service role) which re-grades by VALUE server-side — answers are submitted as option TEXTS (not shuffled indexes) so the client can't be trusted and shuffling doesn't matter; idempotent via `node_progress.credited` CAS.
- Adding a column to `questions` means updating clone_course's explicit column list (fix-forward) — already bitten twice (difficulty, calc); see supabase/CLAUDE.md.
- "Ready course, empty lessons" root cause: the per-chapter question call was try/catch-swallowed, and one truncated/unparseable answer (max_tokens) emptied a whole chapter while the course still flipped ready. Fix: one re-ask per chapter covering only the empty lessons, plus a repair path — generate-course re-claims a 'ready' course that has question-less lessons (count check via nodes→questions(count)).
- In-app credit SPEND RPCs (`purchase_cosmetic`, `buy_food`, `feed_pet`) deduct-then-write inside one transaction but are NOT retry-idempotent: an additive `on conflict do update set qty = qty + excluded.qty` upsert is a second purchase, not a dedupe, so a lost-response retry double-charges. Accepted as in-app-currency debt (bounded by the user's own balance, and consistent across all three) — if a spend ever needs real idempotency, thread a client key into a unique `(user_id, key)` ledger row, don't special-case one RPC. (Real-money charges still follow the Payments rules.)
- React component/hook tests (added 2026-06): the convention is `@testing-library/react` + `@testing-library/user-event` + `happy-dom` (all dev-only, pinned). Each component/hook test file opts into a DOM with a top `// @vitest-environment happy-dom` docblock — do NOT set a global `environment` in vite.config, so the node-env service/lib suites stay fast/untouched. `vite.config` only adds `setupFiles: ['src/test/setup.ts']`, which runs `afterEach(cleanup)` and is a safe no-op in node env (cleanup() no-ops when nothing was mounted). NO jest-dom is installed — assert on plain DOM props (`(btn as HTMLButtonElement).disabled`), not `toBeDisabled()`. Components that import a service (which imports `supabaseClient`, throws without env) must `vi.mock('../../lib/supabaseClient', …)` like the service tests do — driving the real service through a mocked client `invoke` is cleaner than mocking the service. `<Link>`/router components need a `<MemoryRouter>` wrapper.
